# Сохранение AI-групп, ролей и приказов

Living War сохраняет AI-группы в `profileNamespace` вместе с состоянием кампании. Идентификатор записи строится как `сторона:позывной`, поэтому новый объект группы после перезапуска можно сопоставить со старой записью.

Для каждой группы сохраняются:

- сторона;
- русскоязычный позывной (`ЗАПАД-1`, `ВОСТОК-1`, `СОЮЗ-1`);
- роль `QRF`, `GARRISON` или `PATROL`;
- район;
- текущая позиция и направление;
- текущий приказ Director;
- количество потерь;
- текущая экипировка каждого живого бойца;
- позиция, направление и урон каждого живого бойца.

Через 20 секунд после старта сервера `LW_fnc_restoreAIState` пытается сопоставить сохранённые записи с уже созданными Antistasi-группами той же стороны. Приоритет сопоставления: тот же позывной, затем та же роль в радиусе 3500 метров, затем ближайшая группа той же стороны. Восстановление применяется только к группам без игроков.

## Потери и реакции Director

Перед стратегическим тиком сервер сохраняет текущий состав групп. Если численность уменьшилась относительно предыдущего снимка, разница добавляется в `recentLosses` и `losses`.

| Недавние потери в районе | Реакция |
|---:|---|
| 0–1 | обычная реакция по угрозе |
| 2–3 | `REGROUP` |
| 4 и больше | `QRF_REQUEST` |

`QRF_REQUEST` и `REGROUP` передаются через тот же `LW_antistasiDirectorHook`, что и остальные приказы. Конкретное движение группы остаётся за версией Antistasi.

## Ручная проверка

```sqf
call LW_fnc_persistAIState;
private _state = call LW_fnc_getState;
_state get "aiGroups";

call LW_fnc_restoreAIState;
[["town_alpha"]] call LW_fnc_directorTick;
```

Для чистого теста используйте отдельный профиль сервера. Восстановление loadout и позиции является best-effort: если Antistasi не создала подходящую группу или часть бойцов была заменена, восстанавливаются только найденные живые бойцы.
