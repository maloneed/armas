# Автоинициализация и автотест Living War

## Что запускается автоматически

Через 15 секунд после серверного старта Living War выполняет bootstrap. Затем bootstrap повторяется раз в 60 секунд, чтобы увидеть группы и районы, которые появились после запуска Antistasi.

Bootstrap выполняет только discovery и регистрацию supplemental metadata:

- обнаруживает существующие AI-группы;
- фиксирует обнаруженные стороны;
- назначает группе `LW_districtId`, если район ещё не указан миссией;
- создаёт записи районов с безопасными значениями по умолчанию;
- сохраняет счётчики и время последнего bootstrap.

Bootstrap **не создаёт и не удаляет группы**, не телепортирует AI, не меняет владельца locality и не заменяет Antistasi lifecycle.

## Автотест

При старте, а затем раз в пять минут, сервер запускает:

```sqf
call LW_fnc_runAutoTest;
```

Проверяются:

- обнаружение Antistasi;
- состояние кампании;
- выполнение bootstrap;
- реестр существующих AI-групп;
- реестр районов;
- event log;
- количество ошибок и предупреждений.

Полный отчёт хранится в `missionNamespace` как `LW_lastAutoTest` и в `profileNamespace` как `LW_lastAutoTest`. События пишутся в RPT с префиксом:

```text
[Living War][AUTOTEST]
```

В серверной консоли можно вручную выполнить:

```sqf
private _report = call LW_fnc_runAutoTest;
private _clipboardText = call LW_fnc_exportAutoTest;
```

`LW_fnc_exportAutoTest` копирует краткий текстовый отчёт в clipboard. Полный контекст остаётся в RPT; для анализа загрузите RPT и скопированный блок.

## Интерпретация

- `PASS` — проверка успешно пройдена.
- `WARN` — сервер работает, но интеграция или часть данных не подтверждена, например Antistasi ещё не обнаружена.
- `FAIL` — нарушено состояние, необходимое для работы ядра.

Автотест диагностический и не должен считаться доказательством прохождения gameplay-миссии. Для этого нужен отдельный runtime-тест в Arma 3 с реальной Antistasi-миссией.
